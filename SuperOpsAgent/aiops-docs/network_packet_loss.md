# 网络丢包与延迟升高告警处理方案

## 告警名称与影响

- **告警名**: `NetworkPacketLossHigh`
- **触发条件**: 网络丢包率连续 5 分钟超过 1%，或 TCP 重传率、跨服务调用延迟持续高于基线。

网络丢包会导致连接超时、重试增多和请求抖动。应用层常只看到 API 超时或连接重置，需要结合网络指标判断。

## 排查步骤

1. 确认受影响的源、目的、端口和时间范围，区分单服务、单机房还是跨地域链路问题。
2. 查看丢包率、重传率、连接建立耗时、带宽利用率和网络错误计数。
3. 对比同一服务不同实例或不同可用区的调用延迟，定位是否为局部链路。
4. 检查最近网络策略、负载均衡、路由、安全组或带宽配置变更。

## 常见原因与处理

### 原因1：带宽饱和

**特征**：带宽接近上限，峰值时丢包和延迟同步升高，流量下降后恢复。

**处理方案**：限流或削峰；扩容带宽；优化大对象传输和无效流量；避免用无限重试掩盖拥塞。

### 原因2：局部节点或链路故障

**特征**：只有特定实例、可用区或路径异常，其他路径正常。

**处理方案**：摘除异常节点或切换健康路径；收集时间段和路径证据后交由网络团队处理。

### 原因3：网络策略或负载均衡配置错误

**特征**：变更后出现连接重置、端口不可达或仅部分流量失败。

**处理方案**：回滚或修正策略；确认健康检查、目标端口和路由规则；逐步放量验证。

## 验证与预防

验证丢包率、重传率和调用延迟回到基线，连接超时和重试量下降，核心接口成功率恢复。持续监控跨服务延迟、网络错误和带宽余量；网络变更保留回滚方案并进行灰度验证。
