# DNS 解析失败告警处理方案

## 告警名称与影响

- **告警名**: `DNSResolutionFailure`
- **触发条件**: 应用在 5 分钟内持续出现 `NXDOMAIN`、`no such host`、`temporary failure in name resolution` 或 DNS 查询超时。

DNS 解析失败会使应用无法连接数据库、Redis、外部 API 或服务发现地址。因为错误常表现为连接失败，容易被误判为目标服务不可用。

## 排查步骤

1. 从受影响实例执行域名解析，记录域名、返回 IP、错误码和 DNS 服务器地址。
2. 对比同一域名在其他实例、其他网络或其他时间段的解析结果，判断是局部还是全局问题。
3. 检查容器或主机的 DNS 配置、搜索域、缓存和网络策略。
4. 检查 DNS 服务本身的健康度、查询延迟、错误率和最近配置变更。

## 常见原因与处理

### 原因1：域名记录错误或过期

**特征**：稳定返回 NXDOMAIN，所有实例均无法解析，近期有域名或服务迁移。

**处理方案**：修复 DNS 记录；确认 TTL 生效；在变更完成前使用已验证的备用地址仅作为临时措施。

### 原因2：DNS 服务或网络异常

**特征**：查询超时或间歇失败，不同域名都受影响，DNS 服务器延迟和错误率升高。

**处理方案**：恢复 DNS 服务或网络路径；检查负载、节点和网络策略；避免在客户端无限快速重试。

### 原因3：容器 DNS 配置错误

**特征**：仅部分 Pod 失败，配置、搜索域或 NetworkPolicy 与正常实例不同。

**处理方案**：对比 Pod DNS 配置和网络策略；修正错误的 nameserver、search domain 或访问规则；滚动恢复异常实例。

## 验证与预防

验证受影响域名在多个实例解析一致，应用连接错误消失，依赖调用成功率恢复。监控 DNS 查询成功率、延迟和 NXDOMAIN 数；域名和服务发现变更应经过预发布验证。
