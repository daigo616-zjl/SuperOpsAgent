# Redis 服务不可用告警处理方案

## 告警名称

- **告警名**: `RedisUnavailable`
- **告警级别**: 严重
- **触发条件**: Redis Ping 连续失败超过 1 分钟，或应用在 5 分钟内持续出现连接超时、连接被拒绝错误。

## 业务影响

Redis 不可用会导致缓存读取失败、会话丢失、限流失效或分布式锁异常。若应用直接把缓存请求打到数据库，可能进一步引发数据库负载和响应时间上升。

## 排查步骤

### 步骤1：确认服务可达性

检查 Redis 实例进程、端口监听和网络连通性；执行 Ping 验证。若是集群模式，还要确认各节点角色和集群状态。

### 步骤2：检查资源与日志

查看 Redis 日志中的 OOM、loading、AOF 重写、主从断连和故障转移信息；检查内存使用、连接数、命令延迟、CPU 和磁盘 I/O。

### 步骤3：检查应用连接池

确认应用侧 Redis 连接池是否耗尽、连接超时是否过短，以及是否有异常实例持续创建连接。

### 步骤4：评估缓存回源压力

在缓存异常时间段检查数据库 QPS、慢查询和连接池等待数，判断是否发生大规模缓存回源。

## 常见原因分析

### 原因1：Redis 实例进程异常或节点故障

**特征**：Ping 失败、端口不监听、监控显示实例重启或不可达。

**处理方案**：按部署规范恢复实例；检查重启前日志和资源耗尽原因；集群场景确认故障转移是否完成。

### 原因2：内存达到上限

**特征**：日志出现 OOM 命令拒绝；内存使用接近 `maxmemory`；写请求失败但读请求可能仍存在。

**处理方案**：确认淘汰策略是否符合业务；清理不应长期存在的大 Key；必要时扩容内存并优化 TTL。

### 原因3：连接池耗尽或网络超时

**特征**：Redis 本身健康，但应用报连接获取超时；不同应用实例失败程度不同。

**处理方案**：检查连接池上限、空闲连接和连接生命周期；排查网络延迟；避免每个请求创建新连接。

### 原因4：缓存回源放大

**特征**：大量 Key 同时过期或缓存不可用后，数据库 QPS、慢查询和连接等待同步上升。

**处理方案**：对热点数据预热；为过期时间增加随机扰动；对回源增加限流、互斥或降级策略。

## 紧急处理措施

1. 明确 Redis 是整体不可用、部分节点异常还是仅应用连接异常。
2. 对高频缓存回源接口限流或降级，保护数据库。
3. 恢复实例或故障转移后，优先预热热点 Key。
4. 持续观察数据库负载，避免缓存恢复过程造成二次波动。

## 验证步骤

1. Redis Ping、连接数和命令延迟恢复正常。
2. 应用日志不再出现 Redis 连接错误。
3. 缓存命中率恢复，数据库 QPS 和慢查询回落。
4. 核心接口成功率、P99 响应时间稳定 30 分钟。

## 预防措施

- 监控实例可用性、内存、命令延迟、连接数和命中率。
- 为热点 Key 设置预热和失效保护。
- 设计缓存异常时的限流、降级和回源保护。
- 定期演练节点故障和缓存不可用场景。
