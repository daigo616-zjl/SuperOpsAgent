# API 网关限流异常处置手册

## 告警与影响

当网关返回的 429 比例持续升高、某个租户或接口的限流命中量突增时触发告警。正常用户请求可能被拒绝，调用方会重试并进一步放大流量，最终影响核心接口可用性。

## 排查步骤

按路由、调用方和限流规则维度检查 429 日志，确认是全局阈值、单用户阈值还是某条接口规则命中。对比近期发布、配置变更和请求量，判断是业务活动造成的真实流量增长，还是客户端重试、循环调用或攻击流量。检查网关实例的规则版本是否一致，避免少数节点使用了错误阈值。

## 处理与验证

对异常调用方先实施更细粒度的限流或熔断，并修复无退避的重试逻辑。对于经过容量评估的合法流量增长，可临时调整对应路由阈值，同时扩容下游服务，不能只放宽网关限制。确认 429 比例下降、下游延迟和错误率稳定后，固化按租户、接口和优先级区分的限流策略，并持续监控限流命中和重试量。
