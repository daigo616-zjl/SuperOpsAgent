# 配置中心不可用处置手册

## 告警与影响

配置中心请求超时、客户端拉取失败率上升或配置监听连接大量断开时触发告警。新实例可能因无法加载启动配置而启动失败，已运行实例则可能无法获得开关、限流阈值和路由规则的最新变更。

## 排查步骤

确认配置中心 API 健康状态、注册节点数量和存储连接是否正常。按应用维度检查客户端错误日志，区分 DNS、认证、网络超时和服务端 5xx。对比客户端本地缓存的配置版本与配置中心当前发布版本，确认是否只影响配置刷新还是连首次启动也受影响。

## 常见原因与处理

配置中心实例故障或负载过高时，扩容健康节点并将流量从异常实例摘除。后端存储不可用时，先恢复存储连通性和容量，再检查配置发布队列是否有积压。客户端凭据过期或权限调整会导致认证失败，应恢复最小必要权限并轮换失效凭据。网络策略变更造成访问受阻时，恢复客户端到配置中心的 DNS、端口和安全组连通性。

## 验证与预防

验证新启动实例可加载配置，既有实例的监听连接恢复，并确认关键配置版本一致。保留客户端本地缓存和合理的超时重试策略，配置中心部署多副本并对 API、存储、配置发布延迟和客户端连接数建立监控。
