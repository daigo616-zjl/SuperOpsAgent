# 数据库连接池耗尽告警处理方案

## 告警名称

- **告警名**: `DatabaseConnectionPoolExhausted`
- **告警级别**: 严重
- **触发条件**: 数据库连接池活跃连接连续 5 分钟超过最大连接数的 90%，或应用日志连续出现 `Too many connections`、`Connection refused`。

## 业务影响

连接池耗尽后，新请求无法获取数据库连接，通常表现为接口响应变慢、请求超时、5xx 错误率升高；若持续扩大，会导致依赖数据库的服务不可用。

## 排查步骤

### 步骤1：确认连接池状态

查询应用监控中的活跃连接数、空闲连接数、等待连接数和最大连接数。重点确认连接数是否持续上升，以及等待连接是否快速增长。

### 步骤2：检查数据库会话

执行 `show processlist` 或查询数据库会话视图，识别长时间运行的 SQL、长事务和处于空闲但未释放的连接。记录连接来源服务和持续时间。

### 步骤3：关联应用日志

在最近 30 分钟应用日志中检索 `Too many connections`、`Connection refused`、`timeout waiting for connection`。同时确认是否有流量突增、发布或定时任务开始。

### 步骤4：确认连接池配置

检查最大连接数、最小空闲连接、连接超时和连接最大生命周期。比较应用连接池总上限与数据库允许的最大连接数，避免多个实例的上限相加超过数据库容量。

## 常见原因分析

### 原因1：连接泄漏

**特征**：活跃连接只增不减；请求量下降后连接数仍不回落；会话中存在大量同一应用来源的空闲连接。

**处理方案**：临时重启异常实例释放连接；定位未关闭连接、事务或会话的代码路径；修复后增加连接获取、归还和超时指标。

### 原因2：慢 SQL 或长事务占用连接

**特征**：数据库会话中存在耗时 SQL；等待连接数增加；慢查询日志和连接池耗尽在同一时间段出现。

**处理方案**：终止确认无业务影响的异常会话；优化 SQL、索引或执行计划；为事务设置合理超时，避免在事务中执行外部调用。

### 原因3：流量突增或实例连接上限配置过大

**特征**：多个实例的连接数同时上升；请求量明显增长；单实例连接数未异常但总连接数超过数据库上限。

**处理方案**：限流或扩容应用实例前先核算总连接上限；降低单实例最大连接数；按数据库容量调整连接池配置。

### 原因4：数据库本身拒绝新连接

**特征**：数据库日志出现连接数已满、认证失败或网络拒绝；多个服务同时报连接失败。

**处理方案**：确认数据库可用性和最大连接数；清理异常连接；必要时由 DBA 扩容数据库连接能力并复核所有应用连接池上限。

## 紧急处理措施

1. 先确认数据库是否可用以及是否存在异常长连接。
2. 对受影响接口进行限流或降级，保护剩余连接。
3. 在确认影响范围后重启连接泄漏实例，快速释放连接。
4. 若是总量不足，按容量核算后调整连接池或数据库最大连接数，避免盲目提高单项配置。

## 验证步骤

1. 活跃连接数降至最大连接数的 70% 以下。
2. 等待连接数恢复到稳定低位。
3. 应用日志不再出现连接获取超时或拒绝。
4. 核心接口成功率和响应时间恢复正常，并持续观察 30 分钟。

## 预防措施

- 监控活跃、空闲、等待连接和连接获取耗时。
- 为连接池设置连接超时、最大生命周期和泄漏检测。
- 发布前核算实例数乘以单实例最大连接数是否超过数据库容量。
- 定期治理慢 SQL 和长事务。
