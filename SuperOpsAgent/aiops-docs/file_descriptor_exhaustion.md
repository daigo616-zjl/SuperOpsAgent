# 文件描述符耗尽处置手册

## 告警与影响

当进程打开文件数接近限制，或日志出现 `too many open files` 时触发告警。应用可能无法建立新连接、打开日志或临时文件，表现为请求失败率升高、健康检查失败或服务无法继续处理新任务。

## 排查步骤

查看进程的文件描述符限制、当前使用量和增长趋势，识别是单实例还是所有实例受影响。使用系统工具按类型统计已打开的套接字、普通文件和删除但未释放的文件。结合请求量、连接池状态和近期发布记录，判断是否存在连接泄漏、文件句柄泄漏或突发并发导致的容量不足。

## 常见原因与处理

HTTP、数据库或消息连接未正确关闭时，修复资源释放逻辑并重启异常实例回收已泄漏句柄。日志轮转后仍被进程占用的删除文件会持续占用描述符，应修复日志句柄管理并在受控重启后释放。并发连接数增长超过进程限制时，在容量评估后调整文件描述符上限和连接池上限；只提高系统限制而不控制泄漏会掩盖问题。

## 验证与预防

确认描述符使用量回落、`too many open files` 错误停止，并验证新连接和关键请求成功。对打开文件数、连接池活跃连接和描述符增长率设置监控；在压测和发布验证中检查资源关闭路径。
